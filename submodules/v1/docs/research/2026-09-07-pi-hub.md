# Research: pi-hub teardown

_2026-09-07. Source: `~/DotFiles/pi-extentions/pi-hub/`. Local agent supervision platform — the closest existing thing to the "agent server" target: session registry, headless omp workers, reconnect semantics. All refs relative to the repo._

## 1. hub.sock frame protocol

Transport: Unix `SOCK_STREAM` (`$OMP_HUB_SOCK`, default `~/.hub/hub.sock`), NDJSON both directions, per-frame `"v":1`, 1 MiB frame cap, stale socket unlinked before listen. Swap unix path for TCP/WebSocket → remote; nothing in the frame design is local-only.

Frames:
- **hello** (client→hub, first): `{"v":1,"ch":"hello","client":"cli|web|plugin|agent","subscribe":false}` → reply `{"v":1,"ch":"hello","hub":{"version":1,"startedAt"}}`. Major mismatch → `bad-version` + close.
- **report** (fire-and-forget): `{"v":1,"ch":"report","frame":"session_start|user_message|assistant_message|tool_call|agent_end", …}`. `session_start {sessionId, kind: peer|self|worker|agent, cwd, model, attached, title?}` upserts the record; **`attached:true` = pickup of an already-running session**.
- **cmd/reply** (correlated): `{"v":1,"ch":"cmd","cmdId":"<client-minted>","op":"list|send|tool|spawn|kill|attention|answer|assign|archive|agent","args":{…},"by":"…"}` → `{"v":1,"ch":"reply","cmdId","ok":true,"result"}` | `{"ok":false,"error":{code,message}}`. 30 s hub-side deadline (`tool` 120 s when queued); errors-as-values, never throws.
- **deliver** (hub→reporter): `{"v":1,"ch":"deliver","sessionId","text"}` — the ONE inbound mutation; resolves to `pi.sendUserMessage(text)`.
- **event** (hub→subscribed): best-effort fan-out of reporter frames + `attention` + `phase`.
- **error**: `bad-frame | bad-version | unknown-op | forbidden | no-session | timeout | busy`.

**Attach-on-connect** (the key statefulness idea): the reporter owns one reconnecting socket with a bounded outbox (cap 500; >50 dropped wholesale) and backoff 1 s→30 s. On EVERY successful connect it first sends `session_start … attached:true`; the hub upserts by sessionId → reconnects and hub restarts are idempotent (no dup rows, no dup attention). Sessions outlive hubs.

## 2. Worker lifecycle

- `hub_spawn_worker {name?, model?}` → `AgentRuntime.spawn` → `spawn(OMP_BIN, ["--mode","rpc"], {env: {…, OMP_HUB_BRAIN:"1", OMP_HUB_MODEL?}, stdio:["pipe","pipe","pipe"]})`. Duplicate live name → denied. `AgentHandle {name, sessionId: null}` — the child announces its sessionId (reporter session_start / RPC handshake) and the hub observes via the event feed. ([INFERENCE] the handle back-fill is designed but not wired; correlation works via name.)
- `hub_send_message {target, message, wait_seconds?}` → child: **exactly one NDJSON line on the child's stdin: `{"text":"<message>"}\n`**; peer session: `deliver` frame → `sendUserMessage`. Not the full omp RPC protocol — a prompt-only subset; the adapter does not yet parse child stdout.
- `hub_call_tool {target, tool, args}` — direct round-trip possible for workers because the hub holds their stdio pipes; specified (30 s/120 s deadlines, pending-map) but currently returns denied "not served yet". Peer sessions instead get a directive as a user message.
- `hub_kill_worker {name}` → SIGTERM → 5 s grace → SIGKILL; reply `{closedAt}`; archive record per docs (not fully wired).

## 3. Statefulness model

- **status.json** — one JSON doc = every live fact. `version:1` first field (forward compat: unknown fields ignored), `startedAt`, `pid`, `nextAttentionId`, `sessions: Record<id, SessionRecord>` (`status: open|closing`, `kind`, `cwd`, `title`, `model`, `description`, `phase: working|waiting|idle|blocked`, `phaseHistory` capped 50, `log` link, `toolCounts`, `turns`, `startedAt`, `lastActivity`), `attention[]` (open items only), `archived[]` tombstones capped 200.
- **Single writer + atomic rewrite**: tmp + fsync + rename(2); readers never lock; promise-chain write serialization; stale tmp swept; corrupt file = error, never silent reset. (flock on `~/.hub/hub.lock` specified; [INFERENCE] not implemented — exclusivity de facto via socket bind.)
- **logs/<id>.jsonl** — append-only per-session; first line = system event with the session_start frame; lines `{t, sessionId, kind: prompt|tool|result|think|message|system, text ≤2 KB, meta?}`; torn trailing line discarded on read; files outlive sessions (`hub log -f` works while hub is down).
- **summaries.jsonl** — global digest rail (`summary` per turn, `resolution` per attention item with full answer — status.json never holds resolved items).
- **archive/YYYY-MM/<id>.json** — immutable close record: last record + `closedAt, closedBy (cli|web|self|hub-restart|…), finalSummary, resolutions[]`.
- **Hub restart**: sessions that re-announce (`attached:true`) within a **60 s grace** are kept; the rest closed+archived `closedBy:"hub-restart"`. Shutdown does NOT archive open sessions.
- **Worker death**: runtime deletes the child handle (later send/kill → unknown-session); the roster row persists until a close path — staleness visible via `lastActivity`, never silently hidden.
- **Watcher supervision**: bounded backoff restarts (max 5 attempts, 1 s doubling, 5 min stability reset); catch-up pass on restart re-derives phases from status.json instead of replaying events.

## 4. RPC child protocol

Child speaks raw omp `--mode rpc` JSONL on stdio; hub adapter wraps input down to `{"text"}` lines and (today) does not read stdout for replies. No response matching implemented; the round-trip plumbing (pending-map keyed by request id, stdout matching, deadlines) is designed in docs but pending. **Lesson: use the real RPC protocol from day one — the `{"text"}` shortcut forecloses steering, abort, state polling, and tool round-trips.**

## 5. Watcher / hub agent

- Spawn: `OMP_BIN --mode acp`, env `OMP_HUB_AGENT=1` — a PEER session that loads the extension fully and reports over hub.sock; at-most-one with live-child adoption + durable `agentSession` adoption across restarts; refuses to nest (guard: the agent never becomes the hub).
- Phase classification: subscribes to the EventBus, batches events, classifies per batch with TEXT heuristics shared by attention (`approval`-shaped tool lines → waiting; question-shaped assistant text → waiting; `fatal:`/ECONNREFUSED/missing-credential → blocked; user reply clears; agent_end → idle). Unsure → raise nothing. Detection is heuristic — no structured confirmation events.
- Attention: idempotent per OPEN (sessionId, kind); first resolve wins; auto-resolve on phase transitions; idle timer 15 min raises `idle`.
- The agent NEVER writes status.json itself — it asks ops; the hub process writes (single-writer preserved).

## 6. Reusability for the agent server

**Directly reusable**: socket protocol nearly verbatim (swap unix→TCP/WS); attach-on-connect + idempotent upsert + grace reaping; single-doc atomic registry; supervision (bounded backoff, adoption, catch-up); runtime-adapter pattern (ports/agent_runtime.ts — spawn/send/kill, Result errors, adapters never read process.env); anti-recursion guard checklist (brain early-return env flag, self-feed, no self-delivery, attach idempotency, one-hop relay); ops discipline (op registry, cmd/reply, per-op deadlines, errors as values); json/jsonl store adapters.

**Hub-specific (skip)**: attention semantics/classifier, agent personas + agentSurface, widget/CLI/web renderers, omp event translation table, the "brain" composition.

## Open questions
